# HasanAra search and crawl controls

Applied on Almaz October 11, 2026 after Ahrefs topic crawling repeatedly invoked overlapping full-text searches.

The core source change is commit `587dd24a3ab2126de02c58ef03d551e4b5389fbd` on branch `fix/anonymous-search-budget-20261011`, in `/home/onnwee/.local/state/hasanara/search-budget-20261011/core`. The runtime image adds only admission, cache and route/orchestrator changes to the existing efficiency image, preserving availability repairs. The exact image delta, base identity and hashes are under `deploy/search-controls-20261011/`. Those files are recovery artifacts; edit backend code in the core source.

`docker-compose.search-controls.json` pins the tested local image by content ID and sets anonymous concurrency to two. `bin/compose-prod apply-search-controls` reads the live API Compose file list, retains its previous availability and efficiency overlays, verifies that only API image and this environment setting change, and replaces only API without building or pulling dependencies. The pinned image is local to Almaz. It survives normal Docker restart; this is an incident overlay, not a registry-published release. A future full release must include the core patch and reconcile the release manifest and prior incident overlays before deployment.

`deploy/hasanara-crawl-controls.caddy` is imported first inside a route block for hasanara.tv. It returns 429 with Retry-After: 60 to Ahrefs topic/search requests while allowing other page navigation. Its installed copy is `/opt/server/management/config/caddy/sites/hasanara-crawl-controls.caddy`. `frontend/public/robots.txt` ships future web builds and is served now from `/etc/caddy/sites/hasanara/robots.txt`, bypassing the SPA fallback. It excludes all crawlers from API paths and Ahrefs from topics, with a 30-second HTML crawl delay.

Verification passed 12 isolated regression checks, live shared-slot rejection from a separate process across all five expensive routes, forged-cookie rejection, health while full, release cleanup and ordinary validation after release. A filtered live mention-map response populated a 60-second Redis entry; the repeated request reused it, and direct cached retrieval passed with the database search function replaced by a failing stub. Public robots returns text/plain, crawler topic/search calls return 429, and home/readiness return 200. Only the API container ID changed.

Recovery state is `/home/onnwee/.local/state/hasanara/search-budget-20261011/`. It retains Caddyfile.before, the previous API image and Compose file list, and before-container IDs. For rollback, first inspect current changes, restore only the hasanara.tv route from the saved Caddyfile and validate/reload. Recreate only API from the saved Compose stack without the search-controls overlay, retaining availability/efficiency patches. Never overwrite later Caddy changes or run a broad stack deployment as rollback. Database, data mounts, web image and gateway were not changed.

## Registry release transition

The registry API release carries the merged backend source and supersedes the local incident image. Anonymous concurrency two and the 30-second per-statement timeout now live in docker-compose.client.yml. Use bin/compose-prod deploy-api for a preflight-validated API-only rollout. The obsolete apply-search-controls helper and local-image overlay are removed to prevent reapplying the incident pin. Historical runtime build artifacts remain recovery evidence. Crawl controls remain installed independently at Caddy.
